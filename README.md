# VK Маркет · интерактивный пилот

Кликабельный прототип социальной коммерции для **VK Case Champ 2026**. Интерфейс основан на дизайн-принципах VK/VKUI: системные цвета, голубой акцент, белые панели, компактные контролы, плавные переходы и адаптивная сетка. Исходная продуктовая концепция — `VK_Market_pilot_product_spec_2026.docx` (передана командой).

## Как запустить

Проект — статический HTML/CSS/JavaScript, без сборки, npm-зависимостей и серверного API.

```bash
python3 -m http.server 8080
```

Открыть `http://localhost:8080`. Можно также открыть `index.html` напрямую. Подходит для GitHub Pages (корень ветки `main`).

## Покупатель

- Главная с категориями, подборками и подбором товаров из сообществ.
- Поиск и фильтры по категории, наличию, цене, сортировке.
- Карточка товара и страница продавца с переходом в существующее VK-сообщество.
- Избранное, подписки, корзина **одного продавца**, демонстрационный чекаут.
- Профиль и история заказов со статусами.
- Дроп с анонсом, подпиской, управляемым демонстрационным запуском и состоянием «распродано».

## Продавец

- Подключение существующего сообщества (демонстрация проверки прав).
- Обзор: заказы, выручка, товары, остатки, дропы.
- Каталог: добавление/редактирование товара, управление остатками.
- Заказы: смена статуса (новый → подтверждён → сборка → отправлен → завершён), отмена.
- Дропы: создать, анонсировать, запустить, завершить, посмотреть продажи.
- Аналитика → Шопсы: период, источники, открытия карточек, оформленные заказы, конверсия и таблица публикаций.

## Важные ограничения

**Это демонстрационный прототип, не реальный сервис VK.** Товары, продавцы, охваты и продажи синтетические и обозначены как пример. Действия сохраняются в `localStorage` текущего браузера. Реальных списаний, платежей, резервирования между устройствами, доставки и уведомлений VK нет. В демонстрационном чекауте заказ создаётся, но считается **неоплаченным**. Для боевого пилота потребуются backend, атомарный резерв, проверка доступа к сообществу, реальные статусы оплаты и согласованные интеграции VK.

Ссылка на сообщество ведёт в VK; тестовые сообщества/товары вымышлены. Публикации в аналитике представляют демонстрационный пример и не устанавливают реальную атрибуцию заказов. Кнопка «Сбросить демо» удаляет локальные изменения.

## Технологии

Vanilla JS, CSS custom properties, inline SVG; мобильная адаптация, dark mode, `prefers-reduced-motion`, доступные названия кнопок, навигация через URL hash. Изображения 30 демонстрационных товаров хранятся локально в `assets/` и работают без интернета: 16 концептуальных предметных фотографий и 14 тематических векторных иллюстраций. Это визуализации для прототипа, а не фото реально продающихся вещей.

## Кабинет продавца: «Речной Бисквит»

- В этом MVP доступен **один кабинет продавца — «Речной Бисквит»**. Остальные сообщества остаются покупательскими витринами в общем Маркете, но их товары, заказы и публикации не попадают в кабинет «Речной Бисквит». Переключатель магазинов специально не добавлен, чтобы демонстрация не создавала ложное впечатление о подключении нескольких сообществ.
- В **Обзоре** появились средний чек оформленного заказа и корректная статистика только по собственным заказам. Отменённые заказы не учитываются. До первого заказа средний чек обозначен «—».
- В **Аналитике** можно выбрать категорию и отдельный товар из ассортимента магазина. Фильтры применяются к доступным публикациям/шопсам, и отдельная таблица сравнивает категории. Категории без известных публикаций отображают «Нет данных», а не нулевые продажи.
- Метрики шопсов **синтетические**. Сумма и средний чек в блоке «Заказы магазина» вычисляются **из демозаказов в текущем браузере**. Источники намеренно разделены: синтетические заказы из шопсов не прибавляются к оформленным пользователем заказам.
- При фильтрации заказов по категории в средний чек входит **только стоимость товаров этой категории** внутри каждого заказа. Для новых заказов цены фиксируются на момент оформления. Для старых сохранённых демозаказов без снимка цены используется текущая цена товара. Реальная оплата не подключена.


## Актуальное обновление

- Первый экран с выбором режима: покупатель / продавец.
- Город покупателя в демонстрационном сценарии: Рыбинск (не географическое ограничение всего Маркета).
- Кабинет продавца привязан к магазину «Речной Бисквит».
- В карточке товара есть описание, срок доставки, а для товаров на заказ — срок изготовления.
- В карточке заказа и в настройках показаны демо-механики доставки и возвратов.
- Добавлены рейтинг и отзывы покупателей, а в аналитике продавца — блок по оценкам и отзывам.


## Обновление: товарные фотографии, доставка и возвраты

- Для всех 30 демонстрационных SKU изображение соответствует названию товара; кружки показаны кружками, одежда — одеждой, десерты — десертами. Для товаров используется единая молодёжная речная айдентика: синие волны, стилизованные рыбки, кремовый фон и точечные оранжевые акценты. Изображения лежат в `assets/` — **при переносе проекта обязательно копировать папку целиком**.
- Корзина → «Перейти к оформлению»: четыре видимых способа получения — СДЭК (ПВЗ), Яндекс Маркет (ПВЗ), курьер до двери в Рыбинске и самовывоз (только при совпадении города продавца и покупателя). При выборе ПВЗ отображается его тестовый адрес, для курьера запрашивается адрес. Цены, сроки и названия партнёров демонстрационные. Тестовые тарифы не являются предложением реальных перевозчиков.
- Для свежих тортов и пирожных обычные ПВЗ явно показаны как недоступные; в демо покупатель выбирает курьера или самовывоз. Для непортящихся товаров ПВЗ доступны.
- Покупатель → Профиль → «Возвраты и обращения», либо Мои заказы → «Возврат / претензия». Можно выбрать товар и основание, описать ситуацию, выбрать передачу через ПВЗ, курьера или в магазин. Регистрация сразу создаёт номер и историю обращения без предварительного одобрения.
- Продавец видит обращения своего магазина в «Возвратах» и может менять их демостатусы; покупатель видит их в собственном разделе.
- В прототипе нет фактических заказов, отправлений, денежных списаний, возвратов средств, интеграций СДЭК/Яндекс Маркета и юридической проверки права на возврат.

### Как обновить существующий проект

Распакуйте patch-архив **в корень репозитория** с заменой `app.js`, `styles.css`, `README.md` и созданием папки `assets/`. `main` не затрагивается, если вы работаете в `feature/vk-market`. Затем перезагрузите страницу браузера через `Ctrl + F5`.


## География и плавность интерфейса

- VK Маркет предполагается доступным по всей России, а **Рыбинск** — только зафиксированный город покупателя в текущем демосценарии.
- Магазины отправляют товары из разных городов (Рыбинск, Москва, Санкт-Петербург, Новосибирск, Петропавловск-Камчатский). В карточках и чекауте показываются города отправки и ориентировочные сроки до Рыбинска.
- Свежие заказные десерты доступны локально; обычные товары демонстрируют межрегиональную доставку. Сроки и цены условные, API служб доставки не подключены.
- При переключении способа доставки обновляется только содержимое расчёта и адресного блока, без пересоздания модального окна. Подписка изменяет кнопку на месте. У товарных карточек удалены hover-подъёмы и масштабирование фото.
